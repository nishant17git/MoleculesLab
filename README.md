# Molecules Lab

A tactile coin-toss and yes/no decision app: a 3D coin (three.js), smooth motion (GSAP) and a
progressive web app that **works fully offline** after it has been opened once.

No framework, no bundler, no dependencies to install — plain HTML, CSS and ES modules.

## Quick start

```bash
npm start            # dev server on http://localhost:8080  (Node 18+, nothing to install)
npm run build        # regenerate the offline manifest (run after changing any app file)
npm run check        # verify the manifest is current (use in CI / a pre-commit hook)
```

Service workers need `http://localhost` or `https://`; opening `index.html` straight from disk
(`file://`) won't work.

## Project structure

```
index.html                 App shell: loader, UI markup, script/style tags
manifest.webmanifest       PWA manifest (name, icons, display mode)
sw.js                      Service worker — must live at the root so its scope covers the app
precache-manifest.js       GENERATED by `npm run build` (file list + content hashes). Don't edit.

assets/
  audio/                   coin-toss.mp3
  icons/                   favicons, apple-touch-icon, PWA icons (any + maskable)
  images/                  molecules-logo.jpg — 3000px master artwork (not used at runtime)

src/
  css/                     One file per area, loaded in this order from index.html
    base.css               design tokens (CSS variables), reset, typography helpers
    loader.css             intro / loading screen
    layout.css             WebGL stage, UI layer, header, brand, mode switcher
    panels.css             glass panels: coin statistics, yes/no verse
    controls.css           action button, pill buttons
    result.css             big animated result text
    feedback.css           custom cursor, status toast
  js/
    main.js                entry point
    config.js              every tunable: timings, quality presets, storage keys, font list
    app/
      boot.js              start-up sequence (loader ↔ real progress ↔ scene setup)
      toss-controller.js   game logic: toss, decide, mode switching, idle motion
    audio/                 sound + haptics
    pwa/                   service-worker client, install prompt, connectivity
    scene/                 three.js: stage (renderer/loop), lighting, coin, gyroscope, quality
    storage/               crash-proof localStorage + persistent stats
    ui/                    loader screen, mode nav, stats panel, result text, cursor, toast
    utils/                 async scheduling, DOM, device capability, fonts, perf marks

scripts/
  build.mjs                fingerprints files → precache-manifest.js; fills <link rel=modulepreload>
  serve.mjs                zero-dependency dev server (Range-aware)
```

**Conventions:** files are `kebab-case`; modules export factory functions (`createStage`,
`createToast`, …) instead of relying on globals; CSS classes follow `block__element--modifier`;
colours, fonts and easings live in `base.css` variables; all magic numbers live in `config.js`.
three.js and GSAP are classic scripts, available as the globals `THREE` and `gsap`.

## How offline works

After the first online visit, the interface, 3D scene, sound, fonts and libraries are all served
from the browser's cache — the app opens and runs with no connection.

| What | Where it's cached | Strategy |
| --- | --- | --- |
| App files (`index.html`, CSS, JS, icons, audio) | `molecules-precache` | Precached on install, served cache-first. Each file is stored under its content hash. |
| three.js, GSAP | `molecules-runtime` | Cache-first (pinned, immutable versions). Only verified `200` responses are ever stored. |
| Web fonts (CSS + files) | `molecules-runtime` | Stylesheets: stale-while-revalidate. Font files: cache-first. |

- **Updates are atomic and incremental.** Changing a file changes its hash; the new worker
  downloads *only* changed files, then waits. The running app keeps using the old version until the
  user taps **Refresh** in the "Update ready" notice (or the next launch). A half-updated app can't happen.
- **No surprises.** The page never reloads by itself. Going offline/online shows a brief notice and
  nothing else changes — there's nothing in the app that needs a connection.
- **Audio** is answered with proper `206 Partial Content` ranges from cache, so playback and
  seeking work offline (browsers such as Safari require this for cached media).
- **Self-healing.** If the browser evicts a file, the worker re-downloads it; a CDN error page can
  never be cached as a library.
- **Graceful failure.** Opening the app for the very first time without a connection (or with the
  CDNs blocked) shows a clear message with a *Try again* button — never a blank screen.
- Local data (coin statistics) lives in `localStorage`; if storage is blocked or corrupt the app
  continues from memory.

### Workflow: shipping a change

1. Edit anything under `src/`, `assets/`, `index.html` or `manifest.webmanifest`.
2. Run `npm run build`. (Skipping this means existing users won't get the change — `npm run check`
   fails if you forget.)
3. Deploy the folder to any static host over HTTPS (GitHub Pages, Netlify, Vercel, Cloudflare Pages…).
   Everything uses relative URLs, so it also works from a sub-path.

Adding a new JS module needs nothing special: the build follows the `import` graph from
`src/js/main.js`, preloads it, and caches it.

## Performance

- **Fast first paint.** All styles are local and small; the loader paints from HTML + CSS alone
  (its entrance is a pure-CSS animation). three.js/GSAP are `defer`red and font CSS is
  non-blocking, so nothing third-party sits in front of the first frame.
- **Real progress, short and smooth.** The counter reflects actual start-up steps with a short
  minimum duration (`LOADER` in `config.js`). Scene setup, shader compilation and texture upload
  run as separate tasks *before* the exit animation, so the wipe never competes with them.
- **Quality adapts to the device.** `scene/quality.js` picks a preset (low/mid/high) from memory
  and core count, and lowers the render resolution on the fly if frames stay slow. Low-end
  devices also skip the live backdrop blur.
- Profiling: start-up milestones appear as `molecules:*` marks in the DevTools Performance panel.

## Third-party dependencies

| | Version | Loaded from |
| --- | --- | --- |
| three.js | r128 | cdnjs |
| GSAP | 3.12.2 | cdnjs |
| Fonts | Inter, Space Grotesk, Syne, Matangi (Google Fonts); Clash Display (Fontshare) | CDN, only the weights the app uses |

They are fetched once on the first visit and cached; the service worker restricts caching to
exactly these hosts. To remove the CDN dependency entirely, copy the files into a `vendor/` folder,
point the `<script>`/font `<link>` tags in `index.html` at them, add `vendor` to `PRECACHE_DIRS`
in `scripts/build.mjs`, and run `npm run build`.

## Debugging the service worker

DevTools → **Application** → *Service Workers* (tick **Update on reload** while developing),
*Cache Storage* to inspect the two caches, and *Network → Offline* to try the app disconnected.
